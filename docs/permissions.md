# 权限、数据流与已知限制

README 只讲插件能做什么;这份文件讲它要什么、数据怎么走、哪些地方有边界。

## 权限

插件按最小权限申报,当前版本共 10 项:

| 权限 | 用途 |
| --- | --- |
| `ui.panel` | 用命令打开独立面板 |
| `ui.view` | 在右侧工作面板提供界面 |
| `ui.theme` | 生成并安装 PI-Desktop 主题 |
| `clipboard.write` | 复制色值 |
| `clipboard.read` | 读剪贴板历史里的图片(只读) |
| `fs.read` | 读**你自己选择的**文件夹里的图片(不申报 workspace 范围,也没有任何写权限) |
| `agent.complete` | 用你配置的模型生成配色 |
| `models.list` | 在面板里列出可选模型 |
| `agent.tool.register` | 注册 `suggest_palette` 工具供 Agent 调用 |
| `agent.prompt.inject` | 提供配色 skill 文档 |

## 数据流

色板浏览、算法、取色、对比度与导出**全部在本地面板完成**,不联网。需要说明的是另外两件事:

- **AI 配色**只把你输入的那句话或主色交给宿主选定的模型;模型凭据在宿主主进程里解析,插件读不到。
- **主题**是插件生成的一段 CSS,交给宿主**消毒后**再拿去给应用外壳换色;这段 CSS 存在插件自己的设置文件里,面板里随时可以卸载。

插件不访问网络,不读写你的文件,也没有常驻后台服务。模型选择、主题这类偏好由宿主写进插件自己的数据目录(`~/.pi-desktop/plugins/data/<插件 id>/settings.json`),插件本身不直接碰文件系统。

## 已知限制

- **AI 每分钟 8 次**,失败的调用也算一次;单次生成面板最多等 30 秒(宿主转发通道的上限)。
- **剪贴板历史不是系统剪贴板**:只有粘贴进会话的图片会进去,在别的应用里复制截图是看不到的。
- **文件夹授权只在本次运行有效**:一次记一个目录,插件重载或应用重启后要重新选。
- **图片预览上限 5 MiB**,超过会明确提示,不会静默失败。
- **系统级快捷键不在当前版本里**:`Alt+Shift+C` 需要 `keyboard.globalShortcut`,它随宿主 PR #409 落地,但至今没有进任何发布版——插件中心因此不认识这个权限(审计代码 MAN013),而任何可安装的宿主也给不出它。插件在宿主发布后恢复该功能,恢复步骤记在 [PLAN.md](../PLAN.md)。当前用命令面板打开面板。
- **主题需要较新的宿主**:`pi.themes` / `pi.app.setTheme`(ADR 0260)晚于 v0.14.8,同样还没进发布版;旧宿主上导出页的主题区块会直接提示需要更新 PI-Desktop,插件正常加载,其余功能照常。
- **主题只覆盖应用外壳**:插件面板自身的外观不受影响;启动瞬间的原生窗口底色运行期改不到,用的是宿主给当前明暗底色的默认值。
- **主题随插件加载而生效**:宿主的主题注册表在插件卸载或被禁用时会清空,插件每次加载都会重新注册自己存下的那份 CSS,所以重启、禁用再启用之后主题都会回来。
- **取色器里的「屏幕取色」暂时置灰**:它需要宿主开放一次性截屏能力(`screen.capture`),插件侧的放大镜与取色链路已经就绪,宿主一到就能启用。方案与理由见 [PLAN.md](./PLAN.md) §5。
